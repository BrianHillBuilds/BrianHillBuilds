# Brian Hill

Builder and operator focused on practical systems that turn public data, repetitive workflows, and content calendars into useful business tools.

## What I build

- **Data pipelines** that collect, clean, and structure information from public APIs and operational sources
- **Automation tools** that reduce repetitive research, reporting, and scheduling work
- **Web tools and dashboards** that make data easier to review and act on
- **Content systems** for planning, organizing, and consistently publishing work
- **Small, focused utilities** designed to solve one business problem well

## Technical stack

| Area | Tools and methods |
| --- | --- |
| Languages | Python, JavaScript, HTML, CSS |
| Data | REST APIs, Socrata, CSV/JSON processing, SQLite |
| Automation | Scheduled jobs, data validation, report generation |
| Web | Responsive pages, dashboards, forms, and lightweight web applications |
| Workflow | Git, GitHub, documented processes, reproducible scripts |

## Working principles

- Start with a real operational problem.
- Prefer simple, inspectable tools over unnecessary complexity.
- Verify outputs against the source data.
- Document how a system works so it can be maintained.
- Build in small increments and improve from actual use.

## Selected public work

- **Permit Data Explorer** — a Python tool for querying and summarizing recent City of Austin construction permit records by trade keyword.
- **Content Drop Planner** — a lightweight utility that converts a Markdown or CSV content calendar into a sorted posting schedule.
